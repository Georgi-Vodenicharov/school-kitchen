# 🍲 Училищна кухня: ПГ по МСС „Пейо К. Яворов“, гр. Гоце Делчев

**Училищна кухня** е уеб приложение на Django за кухнята на Професионалната гимназия по механизация на селското стопанство „Пейо К. Яворов“ в Гоце Делчев. Работи като системите в ресторантите:

- **меню** с ястия, цени, грамаж, калории и алергени;
- **дневно меню** за всеки учебен ден;
- **поръчки** от ученици: име, клас и избрани ястия;
- **табло на кухнята**, на което персоналът движи поръчките през етапите *Нова → Приготвя се → Готова → Получена*.

> Индивидуален проект за курса **Django Basics** @ SoftUni (септември 2026).

## Функционалности

- **Каталог с ястия** (пълен CRUD): категория, цена в евро, грамаж, калории, алергени, снимка, вегетарианско, наличност.
- **Търсене, филтриране и сортиране** на ястията по име, категория, вегетариански и *„без алерген X“*, с подредба по име, цена или калории.
- **Категории** (създаване, редакция, списък) с поредност, която определя реда в менюто.
- **Алергени** по Регламент (ЕС) № 1169/2011 с номера от 1 до 14, показани до всяко ястие.
- **Дневни менюта** (пълен CRUD): само за учебни дни (понеделник–петък), като в менюто влизат само ястия, които се предлагат. Страницата е оформена като ресторантско меню, с ястията групирани по категории.
- **Поръчки** (пълен CRUD) в две стъпки: първо данни и ден, после добавяне на ястия. Цената на ястието се **запазва в момента на поръчката**, така че по-късна промяна в цената не променя старите поръчки.
- **Табло на кухнята:** активните поръчки в колони по статус, с бутон за преминаване към следващия етап.
- **Бизнес правила:**
  - поръчка може да се променя само докато е *Нова*;
  - ястие или меню, по които има поръчки, не може да бъде изтрито (обработен `ProtectedError`);
  - не може да се поръча за минал ден;
  - не може да се добави ястие, което не е в менюто за деня.
- **Начална страница** с днешното меню, статистики, най-поръчваните ястия и предстоящите менюта.
- Потвърждение преди всяко изтриване, flash съобщения, страниране, собствена 404 страница и адаптивен дизайн без CSS framework.

## Инсталация и стартиране

**Изисквания:** Python 3.12 или по-нов, Git.

```bash
# 1. Клониране
git clone https://github.com/Georgi-Vodenicharov/school-kitchen.git
cd school-kitchen

# 2. Виртуална среда
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# 3. Зависимости
pip install -r requirements.txt

# 4. Миграции
python manage.py migrate

# 5. Стартиране
python manage.py runserver
```

Отворете **http://127.0.0.1:8000/**.

Приложението стартира с **празна база данни**. Не се използват fixtures, data migrations или скриптове за начални данни. Всичко се създава през интерфейса.

## Променливи на средата

За локално тестване **не са нужни** никакви променливи и пароли. Проектът работи с подразбиращи се стойности за разработка.

| Променлива | По подразбиране | Описание |
|------------|-----------------|----------|
| `SECRET_KEY` | ключ за разработка в `settings.py` | Секретен ключ на Django |
| `DEBUG` | `True` | `False` показва собствената 404 страница |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | Разрешени хостове, разделени със запетая |

Не е нужен администраторски акаунт.

### Как да видите 404 страницата

```bash
# Windows (PowerShell)
$env:DEBUG="False"; python manage.py runserver
# macOS / Linux
DEBUG=False python manage.py runserver
```

След това отворете несъществуващ адрес, например http://127.0.0.1:8000/menu/9999/.

## Как да тествате приложението

Всички страници са достъпни от навигацията и footer-а.

1. **Ястия → Категории → + Нова категория:** например *Супи* (ред 1), *Основни ястия* (2), *Десерти* (3).
2. **Ястия → Алергени → + Нов алерген:** например *1 – Глутен*, *3 – Яйца*, *7 – Мляко*.
3. **Ястия → + Ново ястие:** добавете няколко ястия с цена и алергени.
4. **Дневно меню → + Ново дневно меню:** изберете учебен ден (днес или по-късно) и отметнете ястия.
5. **+ Нова поръчка:** въведете име и клас (напр. `10Б`) и изберете деня. На следващата стъпка добавете ястия.
   *Опитайте грешни данни:* клас `15Х`, събота за дата на менюто, количество 0 или над 10, едно и също ястие два пъти.
6. **Кухня:** преместете поръчката през етапите. След „Приготвя се“ поръчката вече не може да се редактира.
7. Опитайте да изтриете ястие, което е поръчано. Ще получите съобщение, че не е позволено.
8. Разгледайте **Началото** (статистики) и използвайте филтрите в **Ястия** и **Поръчки**.

## База данни

```
Category ──< Dish >──< Allergen
              │  ▲
              │  └──< DailyMenu (M2M)
              │            │
              ▼            ▼
         OrderItem >── Order
```

| Модел | Основни полета | Връзки |
|-------|----------------|--------|
| `Category` | name (уникално), position | – |
| `Allergen` | number 1–14 (уникално), name | – |
| `Dish` | name, price, weight_grams, calories, description, image_url, is_vegetarian, is_available | **FK → Category** (many-to-one), **M2M → Allergen** |
| `DailyMenu` | date (уникална, само делничен ден), title, note | **M2M → Dish** |
| `Order` | customer_name, class_group, status, note, created_at, updated_at | **FK → DailyMenu** |
| `OrderItem` | quantity (1–10), unit_price (запазва се автоматично) | **FK → Order**, **FK → Dish**, уникална двойка (order, dish) |

Ограничения на ниво база: уникални имена и номера, `UniqueConstraint` върху (order, dish), `CheckConstraint` за положителна цена и количество, `on_delete=PROTECT` за ястия и менюта с поръчки.

## Форми и валидации

| Форма | Особености |
|-------|-----------|
| `DishForm` / `DishDeleteForm` | Етикети, placeholders, help texts и съобщения на български; алергените като отметки. Валидира цена над 0, грамаж и калории в разумни граници и уникално име без значение от главни/малки букви. Формата за изтриване е изцяло само за четене. |
| `CategoryForm`, `AllergenForm` | Уникалност без значение от регистъра; номер на алерген от 1 до 14. |
| `DailyMenuForm` / `DailyMenuDeleteForm` | Датата трябва да е делничен ден, а при създаване не може да е в миналото. Изисква поне едно ястие и предлага само ястия, които се предлагат. |
| `OrderCreateForm` / `OrderEditForm` | Името е поне 2 думи, само букви. Класът е във формат `8А`–`12Е`. При създаване се избират само днешни и бъдещи менюта. При редакция **менюто е само за четене**. |
| `OrderStatusForm` | Само статусът е за редакция, останалите полета са само за четене. |
| `OrderItemForm` | Ястието се избира само от менюто за деня на поръчката. Количеството е от 1 до 10 и едно ястие не може да се добави два пъти. Цената (`unit_price`) е изключена от формата и се попълва автоматично. |

## Собствени template филтри и тагове

Дефинирани в `common/templatetags/kitchen_tags.py`:

| Име | Вид | Пример | Резултат |
|-----|-----|--------|----------|
| `euro` | филтър | `{{ 2.5\|euro }}` | `2,50 €` |
| `status_class` | филтър | `{{ order.status\|status_class }}` | `badge-ready` |
| `nav_active` | simple tag | `{% nav_active 'menu' %}` | `active` за текущия раздел |
| `allergen_badges` | inclusion tag | `{% allergen_badges dish %}` | рендерира номерата на алергените |

Използвани вградени тагове и филтри: `regroup`, `querystring`, `url … as`, `with`, `now`, `include … with`, `date`, `time`, `timesince`, `truncatewords`, `truncatechars`, `linebreaks`, `linebreaksbr`, `default`, `yesno`, `slice`, `length`, `capfirst`, `lower`, `stringformat`, `add`.
